1. HIGH-LEVEL WORKING WORKFLOW (HOW THE SYSTEM OPERATES)
================================================================================

--------------------------------------------------------------------------------
FLOW A: EMPLOYEE DAILY ATTENDANCE JOURNEY (PUNCH IN / OUT)
--------------------------------------------------------------------------------
1. EMPLOYEE OPENS APP / WEBSITE:
   - Employee opens the Android APK or visits https://smart-attendance-u7e6.onrender.com
   - Enters Employee Code (e.g., EMP001) and Password.
   - The system checks credentials with salted password hashing (app/auth.py).
   - If role is 'employee', system automatically redirects to /dashboard.

2. PUNCH SCREEN (app/templates/emp/punch.html & app/static/js/punch.js):
   - Employee taps "Punch Check-In" or "Punch Check-Out".
   - STEP 1 (GPS Geofencing):
     * Browser/Phone captures exact latitude, longitude, and accuracy radius.
     * Sends coordinates to `/api/geo-check`.
     * System computes distance using the Haversine formula (app/services.py).
     * If distance <= office radius + tolerance (default 200m), GPS turns GREEN.
     * If employee has an approved On-Duty (OD) request, GPS check is bypassed.
   - STEP 2 (Front Camera & Biometric Challenge):
     * Phone's front-facing camera turns on.
     * System issues a random biometric liveness challenge from `/api/challenge`
       (e.g., "Blink twice", "Smile", "Turn head left").
     * Captures consecutive face frames and calculates motion score to guarantee
       a real human face is present (prevents photo/screen spoofing).
   - STEP 3 (Final Verification & Submit):
     * Employee taps the button. Payload is sent to `/api/punch`.
     * The selfie photo is securely stored on disk.
     * Attendance record is created or updated in the SQLite database.

--------------------------------------------------------------------------------
FLOW B: SHIFT 1 VS SHIFT 2 DYNAMIC DETECTION
--------------------------------------------------------------------------------
The system automatically classifies employees into the correct shift based
on actual punch time:

- SHIFT 1 (Day Shift): 08:00 AM to 08:00 PM (12 Hours)
  * If employee punches in between 06:00 AM and 01:59 PM:
    Stored and tracked under Shift 1.
- SHIFT 2 (Night Shift): 08:00 PM to 08:00 AM (12 Hours)
  * If employee punches in between 06:00 PM and 05:59 AM:
    Stored and tracked under Shift 2 across midnight.

--------------------------------------------------------------------------------
FLOW C: CATEGORY-WISE RULES & OVERTIME (OT)
--------------------------------------------------------------------------------
Every employee belongs to one of three categories:
1. STAFF:
   - Standard: 10 Hours/day | Overtime: 0 Hours
2. REGULAR EMPLOYEES:
   - Standard: 12 Hours/day | Overtime: 2 Hours
3. CONTRACT EMPLOYEES:
   - Standard: 10 Hours/day | Overtime: 2 Hours
   - Example: 12 hours worked = 10 Hours Regular Present + 2 Hours Overtime (OT).
   - Daily & monthly registers compute both regular and OT hours separately.

--------------------------------------------------------------------------------
FLOW D: HR ADMINISTRATION JOURNEY
--------------------------------------------------------------------------------
1. HR Admin logs in with code HR001 (default password: damo12345 or 123456789).
2. HR Dashboard (/hr/): Real-time KPI counters (Present, Working, Absent, OD, Leave).
3. Employee Master (/hr/employees): Add, update, assign shifts/categories, delete.
4. Attendance Register (/hr/attendance): Live category & shift filter table.
5. Approvals (/hr/approvals): 1-click Approve or Reject for Leave and On-Duty.
6. Monthly Reports (/hr/reports): Complete 1-to-31 day monthly matrix with Excel export.
7. Settings (/hr/settings): Adjust office GPS location, radius, shifts, and holidays.
8. Audit Ledger (/hr/audit): Tamper-proof log of all logins, edits, and security blocks.

--------------------------------------------------------------------------------
FLOW E: 24/7 CLOUD ARCHITECTURE & MOBILE APP
--------------------------------------------------------------------------------
1. CLOUD SERVER (RENDER.COM):
   - Hosted at: https://smart-attendance-u7e6.onrender.com
   - Runs Gunicorn WSGI multi-threaded server.
2. 24/7 GITHUB HEARTBEAT (.github/workflows/keepalive.yml):
   - Runs every 5 minutes in the cloud to ping /healthz.
   - Prevents Render free-tier from sleeping.
   - Allows mobile app & cloud website to run 24/7 EVEN IF YOUR LAPTOP IS OFF.
3. ANDROID APK (android-sbg/):
   - Standalone native Android wrapper with GPS & camera permissions enabled.
   - Loads the live server URL with seamless touch gestures and offline resilience.

3. FILE-BY-FILE BREAKDOWN (WHAT EACH FILE DOES & WHY IT IS USED)
================================================================================

1. app/__init__.py:
   - WHY IT'S USED: Application Factory. Initializes Flask, registers blueprints, 
     configures reverse proxy handling (ProxyFix), and attaches security error handlers.
   - WHAT IT DOES: Sets up SQLite teardown, attaches before_request interceptors 
     for authentication, CSRF, and WAF cyber defense. Returns JSON for API errors.

2. app/auth.py:
   - WHY IT'S USED: Authentication & Access Control.
   - WHAT IT DOES: Handles /login, /logout, /change-password. Provides decorators:
     * @login_required: Ensures user is signed in.
     * @hr_required: Restricts route to HR administrators only.
     * @employee_required: Directs regular employees to employee portal.
     * check_csrf(): Validates CSRF tokens across forms, headers, and JSON bodies.
     * Login Throttling: Protects against brute-force attacks while preventing DoS.

3. app/employee.py:
   - WHY IT'S USED: Employee Self-Service Portal.
   - WHAT IT DOES: Manages employee dashboard, punch screen view, monthly attendance 
     history, CSV/Excel history export, leave balance tracking, and on-duty (OD) requests.

4. app/hr.py:
   - WHY IT'S USED: HR Management & Operations Portal.
   - WHAT IT DOES: Full CRUD for employees (Add, Edit, Activate/Deactivate, Delete), 
     attendance register view, shift scheduling, approval workflow for leaves and OD, 
     attendance corrections, monthly 1-to-31 day reports with Excel export, and system settings.

5. app/api.py:
   - WHY IT'S USED: REST API Endpoints for Mobile App & Web Punches.
   - WHAT IT DOES:
     * POST /api/geo-check: Evaluates GPS location against office radius and tolerance.
     * POST /api/challenge: Generates random biometric liveness prompts.
     * POST /api/punch: Validates punch, computes duration, assigns Shift 1 or 2, 
       calculates overtime, and stores selfie photo.
     * GET /api/selfie/<name>: Serves encrypted selfie images with role-based checks.

6. app/ai_assistant.py:
   - WHY IT'S USED: Intelligent AI Attendance Assistant.
   - WHAT IT DOES: Answers natural language questions from employees and HR:
     * "How many hours have I worked today?"
     * "What time did I punch in?"
     * "Show Shift 1 present list" (HR only)
     * "Show today's absent employees" (HR only)
     * "What are my leave balances?"

7. app/security_shield.py:
   - WHY IT'S USED: Cyber Defense Shield & Web Application Firewall (WAF).
   - WHAT IT DOES: Inspects incoming requests for SQL injection (SQLi), Cross-Site 
     Scripting (XSS), Path Traversal, and AI Prompt Injection attempts. Blocks attackers 
     with HTTP 403 and records incidents in the audit ledger.

8. app/services.py:
   - WHY IT'S USED: Reusable Business Logic & Mathematical Formulas.
   - WHAT IT DOES:
     * haversine(lat1, lon1, lat2, lon2): Calculates distance in meters between GPS points.
     * determine_shift_from_punch(): Automatically assigns Shift 1 or Shift 2 based on punch time.
     * finalize_attendance(): Calculates working hours, overtime hours, and status (P, HD, A, OT).
     * build_register(): Generates the monthly attendance matrix for reports.

9. app/db.py:
   - WHY IT'S USED: Database Management & Migrations.
   - WHAT IT DOES: Defines database schema, enables WAL (Write-Ahead Logging) mode, 
     executes schema migrations, and seeds baseline shifts, offices, categories, and admin users.

10. config.py:
    - WHY IT'S USED: Centralized Configuration.
    - WHAT IT DOES: Reads environment variables (APP_ENV, SECRET_KEY, DATABASE), sets 
      GPS accuracy limits, geofence tolerance, session lifetimes, and security flags.

11. run.py:
    - WHY IT'S USED: Production Local Server Launcher.
    - WHAT IT DOES: Runs a multi-threaded Waitress WSGI server on port 5000 on Windows.

12. wsgi.py & gunicorn.conf.py:
    - WHY IT'S USED: Cloud Production Server Entrypoints.
    - WHAT IT DOES: Connects the Flask application to Gunicorn on Render cloud with 
      optimized worker concurrency, timeouts, and preloading.

13. render.yaml:
    - WHY IT'S USED: Cloud Deployment Automation.
    - WHAT IT DOES: Infrastructure-as-code for Render.com. Automatically triggers build, 
      installs dependencies, sets environment variables, and launches Gunicorn.

14. .github/workflows/keepalive.yml:
    - WHY IT'S USED: 24/7 Cloud Heartbeat.
    - WHAT IT DOES: Runs on GitHub cloud servers every 5 minutes to ping the Render URL, 
      keeping the server awake even when your laptop is turned off.

15. android-sbg/MainActivity.java:
    - WHY IT'S USED: Android Mobile App Logic.
    - WHAT IT DOES: Loads the attendance web portal in a high-speed Android WebView, 
      bridges GPS hardware and camera permissions, manages session cookies, and handles 
      pull-to-refresh.

4. DATABASE TABLES & DATA STORAGE (SQLite WAL MODE)
================================================================================

1. employees:
   - Stores employee records: emp_code, name, email, phone, role ('hr'/'employee'), 
     shift_id, category_id, office_id, password_hash, active, joined_on.

2. attendance:
   - Daily attendance records: emp_id, date, shift_id, check_in, check_out, 
     in_lat, in_lng, in_dist, out_lat, out_lng, out_dist, in_selfie, out_selfie, 
     work_hours, ot_hours, status ('P', 'HD', 'A', 'OT', 'IN'), late (0/1).

3. shifts:
   - Shift definitions: name ('Shift 1', 'Shift 2'), start_time, end_time, 
     grace_min, full_hours, half_hours, ot_min_hours, active.

4. employee_categories:
   - Category rules: code ('STAFF', 'EMPLOYEES', 'CONTRACT'), work_hours, overtime_hours.

5. offices:
   - Geofence coordinates: name, lat, lng, radius_m, active.

6. leaves & leave_types:
   - Leave applications, quotas (CL, SL, PL), balances, and approvals.

7. od_requests:
   - On-Duty requests with client location, date, purpose, and approval status.

8. audit_log:
   - Security ledger recording actor, action, timestamp, details, and client IP.

9. login_attempts:
   - Tracks failed attempts per IP/code to enforce lockout throttling.
